## Instruction and scope

Implement a deterministic risk-plane package with an independent Risk Gate, dynamic position/risk allocation, durable latched Kill Switch, independent supervisor, fault-injection tests, an auditable test report, and an operator runbook. Follow the canonical MRD and Roadmap Phase 7 requirements. Make all changes on GitHub through the dedicated branch and a reviewable pull request.

## Required controls

- No real orders, order submit/cancel requests, exchange API calls, provider requests, external notifications, model/data downloads, live/dry-run/paper sessions, or host-network changes.
- No changes to main outside the normal reviewed pull request flow. This directive does not authorize merging the Phase 7 pull request.
- Risk code must not import NLP/model services or depend on model confidence to enforce the absolute cap.
- Dynamic parameters must arrive through a versioned policy object. Do not compile an owner-selected daily budget, stake fraction, stop distance, or absolute cap into the allocator.
- The absolute daily-loss cap and gross-exposure cap are immutable inputs to the calculation; loss, open-position risk and unresolved-order risk consume capacity conservatively.
- Account/order snapshots must be reconciled and fresh. Missing policy, snapshot, market rules, stop, allocation, kill-switch state, or risk service health rejects new entry.
- The Risk Gate independently recalculates stop loss, both-side fees and slippage, quantity precision, notional, free balance, exposure and remaining loss capacity.
- The Kill Switch starts latched when its durable store has no known state. It can only be re-armed through an explicit, version-checked manual operation with owner approval and reconciled account/orders. Supervisor restart or healthy heartbeats must never clear it automatically.
- The NLP/model process is not passed the policy-store or Kill Switch controller capability. This repository change does not claim that OS-level process identity and runtime ACLs are already deployed.
- Risk-reducing intents such as EXIT and REDUCE_RISK must bypass entry-only risk denial. This does not itself submit an order.
- CI changes may extend existing checks but must not lower coverage, typing, security, complexity, dependency, runtime or documentation gates.
- Tests and fault injection use deterministic synthetic fixtures only.
- Champion remains null; economic acceptance and trading authorization remain NO-GO until separate, permitted OOS evidence and release gates are approved.

## Evidence required before phase closure

- Exact-head CI success and reviewed logs/artifact.
- Fault matrix with per-scenario pass/fail for absolute cap, bad stop, calibration/confidence degradation, ATR spike, unknown regime, service/API timeout, stale data, supervisor crash, restart and unknown order state.
- Reproducible paired walk-forward/OOS comparison against a simple baseline, including drawdown, CVaR/tail loss, fees/costs, turnover and regime stability, using an authorized versioned dataset and pre-registered thresholds.
- A recorded explanation of any criterion still blocked by missing account-source integration, deployment ACLs, real history or approved economic thresholds.
