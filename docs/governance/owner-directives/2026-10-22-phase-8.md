## Owner decisions

1. The initial operating mode is single-user and local-first. Do not require a separate identity-provider server for the initial owner-only deployment.
2. Local administrative authentication uses one high-entropy Bearer token loaded from an ignored local .env file. Missing/short tokens fail startup; requests without the token fail closed; the token is compared in constant time. Tokens must never be committed, logged, included in images, or passed to a Worker.
3. PostgreSQL is the Control Plane database. Each Worker has a dedicated SQLite database on its own named Docker volume. Compose exposes PostgreSQL only on an internal network and publishes the Control Plane API only on 127.0.0.1.
4. Every Worker runs in its own non-root container with a read-only root filesystem, dropped Linux capabilities, no-new-privileges, CPU/memory/PID limits, a scoped internal network, and a dedicated writable state volume.
5. The Control Plane container never mounts the Docker socket. Container lifecycle commands are executed by a trusted host-side dispatcher using the Docker CLI and a fixed Compose worker service. This dispatcher has owner-level Docker authority and must run only on the owner's controlled machine.
6. OIDC is an extension point, not an active Phase 8 feature. The current server rejects unsupported auth modes rather than silently falling back.
7. Phase 8 CI and the local Compose worker are synthetic-only. The Worker implementation in this phase records identity and heartbeat only; it must not import or start Freqtrade, connect to an exchange, or place/cancel an order.
8. Existing Risk Gate and latched Kill Switch contracts remain unchanged. order_permission remains false, Champion remains null, economic acceptance remains NO-GO, and trading authorization remains NO-GO.

## Scope and required controls

- Implement tenant, membership, account-binding, worker-profile, lifecycle-command, scoped worker credential, heartbeat, and audit contracts.
- Enforce tenant ownership in transactional repository operations. Never treat caller-supplied tenant IDs as proof of authorization.
- Store only secret references for future exchange credentials; no raw exchange key or secret is accepted by the Control Plane API.
- Worker credentials are generated by the trusted host-side dispatcher; only SHA-256 digests are stored in PostgreSQL. Worker credentials are generation-scoped and invalidated at stop/disable.
- The runtime dispatcher accepts only a pre-defined Compose service and fixed command path. The Docker socket is not mounted into the API or Worker.
- Tests use temporary SQLite databases, synthetic tokens and mocked Docker commands. No external exchange/provider calls, live credentials, data/model downloads, trading sessions or host networking changes are permitted in CI.
- All changes occur on the dedicated branch and a reviewable PR. Do not merge without a separate explicit Owner instruction.
