# ADR-045: Trial-Count Accounting and DSR Feasibility

- **Status:** Accepted — accounting semantics and feasibility boundary only
- **Date:** 2026-11-15 UTC
- **Branch:** research/nobitex-hf-strategy
- **Evidence baseline:** 104bf2bb9bd54bdfe06c5f5895a846f28e29f652
- **Related:** ADR-012, ADR-038, ADR-042, ADR-043, ADR-044
- **Inventory:** docs/research/accounting/GLOBAL_N_INVENTORY.md
- **Owner decision:** no strategy, trial, or execution option is selected by this ADR.

## Context

The repository contains 27 ml-core-v4 workflow files alone. A complete tree inspection identifies 39 research- or research-adjacent workflows when the 27 are combined with the other 11 historically inventoried research workflows and four-arm-real-experiment.yml. The earlier “eight paths” description is therefore not a complete inventory of the experiment/search surface. A workflow file is not automatically a trial: several workflows are diagnostics, nested searches, repeated validation, or replays of candidate IDs created elsewhere.

The historical Trial Registry records a non-HF subtotal of at least 7,912 while explicitly retaining GLOBAL_N=UNKNOWN. V4-T includes 32 top-level candidate IDs and 36 nested configurations with unresolved overlap; DEAP includes 7,842 verified genomes plus 828 owner-reported genomes with unresolved overlap; HF has 41 workflow records/42 attempts but an unknown count of unique economic configurations. Failed executions may also contain partial candidate work.

DSR has two separate historical-data dependencies:

1. the number of independent candidate trials, N, in the relevant selection family; and
2. the observed Sharpe distribution across those trials (including dispersion), together with the selected candidate's own Sharpe/return-shape inputs.

Neither a run count nor a workflow-file count satisfies the first dependency. PF, QLIKE, trades, forecast origins and optimizer timesteps do not substitute for the second.

## Decision

### 1. Independent trial unit

For AliX DSR accounting, an **independent trial** is one distinct, pre-identifiable candidate decision rule evaluated or compared within a selection family on a declared data/protocol scope. Candidate-defining identity includes, as applicable:

- model family and immutable model/code revision;
- feature set, label/target definition and forecast-to-decision adapter;
- market, timeframe, horizon and data snapshot;
- parameter values, thresholds, strategy/entry logic;
- exit/trade-management and risk policy;
- cost/fill assumptions when those assumptions are part of candidate selection;
- preregistered objective/selection rule and evaluation boundary.

A new value of a candidate-defining parameter creates a distinct candidate trial even when it belongs to the same hypothesis family and is generated by the same workflow grid. Thus one hypothesis family may contain many independent trials. Family identity groups the trials; it does not collapse parameter alternatives into one trial.

A nested hyperparameter configuration is a candidate alternative when its score is used to select or reject it. Its fold fits are repeated evaluations of that configuration, not additional independent trials. A genome is a candidate genotype; a unique genome actually evaluated is counted in a genome-based search ledger, while repeat appearances of an identical genome are deduplicated.

### 2. Unit separation

These terms MUST NOT be conflated:

- **Genome:** one unique encoded genetic-programming candidate. Count a unique genome once if evaluated; repeated population appearances do not create new genomes.
- **Config/candidate:** one unique model/strategy/parameter/decision-rule alternative. Parameter-distinct candidates within a family count separately.
- **Execution:** one workflow run/process invocation. It may evaluate zero, one or many candidates.
- **Attempt:** one execution attempt, including reruns/retries. An attempt is not a trial count.
- **Fit/fold/forecast/trade/timestep:** compute/evaluation observations attached to a candidate; they are not independent candidates by themselves.

The inventory records these units separately and does not sum heterogeneous units without a candidate-level crosswalk.

### 3. Repeated references and overlap

Exact repeated references to the same effective candidate, same data snapshot and same decision rule are deduplicated for DSR N and for the Sharpe distribution. Their individual registry rows remain append-only provenance records.

Run #10 Arm A at 120/180/240 bps is the explicit example: three registered cell IDs point to one threshold-invariant Donchian control and identical trade series. Retain all three rows, but count one effective Arm-A candidate/Sharpe observation. The cohort's 12 registered IDs correspond to 10 effective signal rules.

Different parameter values, thresholds, features, labels, model revisions or exit policies are distinct trials when they represent selectable decision rules. A cost-only sensitivity replay is not automatically another strategy trial if it is a fixed robustness report and is not used to choose a candidate. If the cost/fee/slippage setting is itself searched or used to select the winner, all compared alternatives must be preregistered and included in the relevant selection accounting.

Workflow replays of inherited candidates (for example V4-I through V4-O) retain parent candidate IDs. A replay must not be added as a second model candidate solely because a new workflow file or run ID produced the same candidate. If the replay changes a candidate-defining decision rule, it is a new child config with a parent link.

### 4. Failed and incomplete executions

A workflow execution/attempt that fails during setup, import, dependency installation or preflight before any candidate evaluation is not a candidate trial.

A failed, cancelled or partial execution **does count** for each candidate that reached an actual model/parameter evaluation or whose candidate score/output was inspected for selection. Rejected candidates and candidates that fail a sample/quality gate after candidate evaluation remain in the multiplicity ledger; excluding them would condition N on the result.

If available evidence does not establish whether a failed attempt reached candidate evaluation, status is UNKNOWN_PARTIAL_PROGRESS; do not set the count to zero. Its unresolved candidate identities must be listed as an accounting gap and included in any future conservative cohort resolution.

Workflow execution count, retry count, training timestep count and fold-fit count are not acceptable proxies for unresolved candidate count.

### 5. DSR input contract

A DSR result is admissible only when all of the following are available and linked:

1. a reconciled, deduplicated list of candidate trial IDs in the selection family;
2. a defensible N for that family, including failed/rejected/partial candidate alternatives that reached evaluation;
3. one comparable Sharpe estimate for each eligible candidate, computed under a declared common return frequency, return construction and cost/fill protocol;
4. the selected candidate's Sharpe and return-distribution inputs (at minimum the required variance/standard-error term and return-shape moments under the selected DSR implementation);
5. an explicit independence/dependence treatment and sensitivity when candidate returns are correlated.

A valid Sharpe list without a complete N is insufficient. A valid N without the Sharpe distribution is also insufficient. Missing Sharpe values MUST NOT be imputed from PF, total return, win rate, QLIKE, trade count or forecast statistics.

### 6. Inventory finding and eight-path correction

The tree contains **27 V4 workflow files** and **39 research/research-adjacent workflow files** in the reviewed scope. This count is evidence of a larger experiment and researcher-degrees-of-freedom surface than the earlier “eight paths” summary; it is not a claim of 39 independent strategies or of a 39-trial lower bound.

The workflow inventory records explicit grid dimensions and replay relationships. It also identifies diagnostics and mock/validation workflows that create no economic trial, inherited-candidate replays, nested configs, repeated candidate references, and missing historical execution artifacts.

### 7. Global N and present DSR status

The prior audited non-HF subtotal remains **N ≥ 7,912 as recorded in the Trial Registry**, not a replacement for GLOBAL_N. That subtotal is heterogeneous and contains unresolved overlap. The workflow inventory does not justify adding its per-run grid sizes to that subtotal because candidate identities and inherited/replayed configurations have not all been reconciled.

The finite conservative upper bound is unavailable: historical failure attempts, HF unique economic configurations, the DEAP 828-genome owner report, V4-T nested configs, older branches and partial candidate work are incomplete or have unresolved overlap.

The retained Sharpe evidence is also incomplete. V4-AP has 36 documented Sharpe estimates. V4-AI/AO computes candidate Sharpe and DSR for its current-run cohort, while explicitly excluding historical trials and leaving independence unverified. For the other major historical families, a complete candidate-level Sharpe series is not evidenced in the retained registry/artifacts. Accordingly, DSR is not computable for the global historical family even if N were supplied tomorrow.

Do not substitute an arbitrary N, a fabricated Sharpe variance, or a made-up worst-case distribution. Keep GLOBAL_N=UNKNOWN and DSR MISSING / NOT_COMPUTABLE until both inputs are reconstructed. Once full Sharpe distributions are available, increasing N generally raises the expected maximum Sharpe and makes the DSR hurdle more stringent; the magnitude cannot be calculated without the actual Sharpe distribution and declared dependence treatment.

## Consequences

- docs/research/accounting/GLOBAL_N_INVENTORY.md is the durable, read-only inventory baseline.
- TRIAL_REGISTRY.md remains append-only and receives no new trial entry in this accounting turn.
- ADR-042 and all twelve Run #10 rows/verdicts remain unchanged.
- ADR-043 remains prospective only; this ADR does not retroactively label Run #10 FUTILE.
- No threshold, model, strategy, execution lock, trigger, holdout, data artifact or frozen main branch is changed.
- Future preregistrations must assign a canonical trial_id, plus parent/duplicate references, before any candidate output is evaluated.

GLOBAL_N=UNKNOWN remains the only defensible global status.

Architecture First. Evidence Always. Fail Closed.
